# Phase 2 – Requirement Analysis
## Functional Requirements
1. Apply the UI Policy to the Incident table.
2. Trigger it when Impact is 1 – High.
3. Make Assignment Group mandatory.
4. Make Urgency read-only.
5. Set Urgency to 1 – High when Impact changes to High.
6. Prevent submission when Assigned To is empty for High Impact.
7. Block direct State editing from the Incident list.
8. Allow State changes from the Incident form.
9. Reverse UI Policy behavior when Impact is not High.

## Non-Functional Requirements
- Simple and maintainable configuration.
- Clear user feedback.
- Works within the ServiceNow Incident interface.
- No external software required.

## Skills
Incident Management, UI Policies, UI Policy Actions, Client Scripts, JavaScript, Form Validation.
